# 保守と回帰判断

## 目的

既存スキルの大幅改修や将来の変更で、何を比較し、何を承認してから壊してよいかを明確にする。

## 読むタイミング

既存スキルを変更する前、または破壊的変更・回帰確認の要否を決める時点。

## 判断手順

1. **変更前比較の要否を決める**
   - 変更前の挙動、成果物、評価結果のどれを比較対象にするかをユーザーと決める。
2. **回帰候補を列挙する**
   - トリガー
   - 参照パス
   - 段階的開示の読込順
   - `skill-creator` との境界
   - 既存挙動
   - 既存の停止条件と引き渡し条件
3. **破壊的変更を分離する**
   - 必須項目の削除、責務変更、参照先の統合や削除、境界変更は承認前に実施しない。
4. **未検証を残す**
   - 比較できなかった点、環境差分、未実施の検証を報告に明記する。

## 報告で残すこと

- 何をベースラインとして比較したか
- どの回帰候補を検証したか
- 承認済みの破壊的変更は何か
- 未検証事項と追加で必要な確認は何か
