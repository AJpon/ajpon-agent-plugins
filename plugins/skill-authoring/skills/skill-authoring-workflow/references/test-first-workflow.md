# テスト先行ワークフロー

## 目的

対象スキルの変更前に、何をもって合格とするかを先に決める。

## 読むタイミング

設計案が見え、実装前に eval と検査方法を合意したい時点。

## 手順

1. **対象挙動を定義する**
   - 通常ケース、曖昧な依頼、境界ケースを候補にし、期待する質問・判断・停止条件を先に書く。
2. **テスト方式を選ぶ**
   - 行動 eval、形式検査、内部リンク検査、人によるレビューから必要なものを選ぶ。
3. **ベースラインを決める**
   - 新規スキルでは「スキルなし」をベースラインにする。
   - 既存改修では、案件ごとにユーザーと合意した変更前挙動や変更前成果物をベースラインにする。
4. **合格基準を固定する**
   - 実装後に都合よく基準を弱めない。失敗したら実装か設計を見直す。
5. **RED → GREEN → REFACTOR**
   - 先に失敗を定義し、最小変更で通し、最後に重複や過剰実装を整理する。

## 必須の確認

- 相対リンクが解決すること
- frontmatter の `name` と `description` が設計どおりであること
- 行動 eval を実行できない場合、その理由と代替確認の限界を明示すること

必要なら、合意した検証内容を [../templates/test-plan.md](../templates/test-plan.md) に記録する。
